## 0. 시작하기 전에 — Rocky Linux 10에서 반드시 알아야 할 변경점

| 항목 | Rocky 8/9 방식 | Rocky 10에서 달라진 점 | 이 가이드의 대응 |
|---|---|---|---|
| 네트워크 설정 | `/etc/sysconfig/network-scripts/ifcfg-*` 파일 사용 가능 | 레거시 `ifcfg` 스크립트 지원이 완전히 제거됨(NetworkManager keyfile만 지원) | 모든 인터페이스/본딩 설정을 `nmcli`로만 수행 |
| PostgreSQL | `dnf module enable postgresql:15` 후 설치 | 모듈러리티(AppStream 모듈) 자체가 폐지되어 `dnf module` 개념이 사라짐. 기본 저장소는 **PostgreSQL 16** 단일 버전만 제공 | **PostgreSQL 16을 그대로 채택**(위 개정사항 1번 참고). 로컬 저장소(§4-6)로 그대로 설치 |
| OpenJDK 17 | `dnf install java-17-openjdk` | Rocky 10 AppStream에는 17 패키지 자체가 없고 21/25만 제공 | `java-21-openjdk` 사용 |
| Tomcat 9 | 배포판에 따라 tar 설치가 일반적 | Rocky 10 AppStream에 `tomcat9` RPM이 그대로 존재 | **RPM(`tomcat9`) 설치**로 통일(§5-2) — 실제로도 이 방식으로 진행됨 |
| lvm2 | 대부분 기본 이미지에 포함 | 이 프로젝트의 Vagrant Rocky10 박스에는 **lvm2가 기본 설치돼 있지 않음** | 로컬 저장소(§4-6) 다운로드 목록에 `lvm2` 명시적으로 포함 |
| CPU 요구사항 | x86-64-v2 이상이면 동작 | x86-64-v3 이상 필수(v2 지원 종료) | 2013년 이후 CPU면 대부분 문제없음. 부팅 안 되면 이 부분 의심 |
| 방화벽/SELinux 기본 정책 | 동일 | 큰 변화 없음(nftables 백엔드, SELinux enforcing 기본) | Rocky 9와 동일하게 진행 |

전체 네트워크/서버 구성은 원본 구성도와 동일합니다.

```
관리망(Management)  192.168.10.0/24   GW 192.168.10.1
서비스망(Service)    10.10.10.0/24     GW 10.10.10.1   (bond0, mode=1 active-backup)

web01  Presentation  관리 192.168.10.111  서비스 10.10.10.11
was01  Application   관리 192.168.10.112  서비스 10.10.10.12
db01   Data          관리 192.168.10.113  서비스 10.10.10.13(기본) / 10.10.10.23(예약 — §16에서 db_vip가 됨)

트래픽 흐름: 사용자 → Apache(web01:80) → AJP → Tomcat(was01:8009) → JDBC → PostgreSQL(db01:5432)
```

**서비스망(10.10.10.0/24) 주소 정리표 — 모든 챕터 공통이며 절대 겹치면 안 됩니다** (v16 신설):

| 주소 | 주인 | 등장 챕터 |
|---|---|---|
| 10.10.10.11 | web01 | §3 |
| 10.10.10.12 | was01 | §3 |
| 10.10.10.13 | db01 (기본 IP) | §3 |
| 10.10.10.14 | web_vip (플로팅 IP) | §10 |
| 10.10.10.15 | was_vip (플로팅 IP) | §10 |
| 10.10.10.21 | **web02** (노드 IP) | §9 |
| 10.10.10.22 | **was02** (노드 IP) | §9 |
| 10.10.10.23 | db01의 예약 IP → §16에서 db_vip(플로팅 IP)로 전환 | §3 / §16 |
| 10.10.10.24 | db02 | §11 |
| 10.10.10.25 | witness01 | §16 |

> ⚠️ **web01/was01의 bond0에는 `.21`/`.22`를 붙이지 않습니다.** v15까지는 "서비스 IP"라는 이름으로 web01/was01 bond0에도 `.21/.22`를 두 번째 주소로 붙이게 했는데, 이 주소는 Phase 2에서 web02/was02의 노드 IP가 되므로 **IP 충돌**이 납니다(v16 업데이트 1번). 이 가이드에서 bond0에 IP를 2개 갖는 노드는 db01(`.13` + `.23`) 하나뿐입니다.
